# Report template

Use this shape for the Phase 5 report, in chat (`full`) or in `gerrit-review-fix-plan.md` (`audit`).

```markdown
# gerrit-review-fix plan — change <number>

## Provenance

- Change: <number> · <subject>
- Project: <project>
- Target branch: <target> (from Gerrit, not from the local branch)
- Remote: <remote> · Base: `merge-base HEAD <remote>/<target>` = <sha>
- Local branch: <name or "detached"> · Local head: <sha>
- Patchset reviewed: <n> (current: <n>) · Revision match: yes
- Votes: <account> Code-Review -1 · <account> +1 (who currently blocks)
- Tree: clean | dirty (<files>)
- Generated: <date>

## Summary

- Accounts: <name> (bot) · <name>, <name> (human) — say which you treated as bots
- Bot reviewed patchset: <n> of <current n> — current | behind (findings may be incomplete)
- Comments: <n> total, <n> unresolved, <n> findings after collapse (<n> chatter dropped)
- Bot: <n> findings — live <n> · stale <n> · wrong <n> · blocked <n>
- Human: <n> findings — live <n> · stale <n> · wrong <n> · blocked <n> · question <n> · nit <n>
- Threads waiting on a reviewer (owner spoke last): <n>
- Dropped paths: <paths or none>
- Authors out of scope this run: <none, or who and why>

## Findings

### F1 — <one-line title>

- From: <account> (human, blocking) · thread of <n> · comment id `<hash>`
- Sites: `path/to/file.ts:120` (+3 more: :145, :201, :288)
- Says: <the claim or request, one sentence — the LAST message in the thread>
- State: live
- Fix: <the concrete edit, one or two sentences>
- Reply: <the text to post once the fix lands>
- Risk: low
- Status: proposed

### F2 — <one-line title>

- From: <account> (bot) · comment id `<hash>`
- Sites: `path/to/other.ts:44`
- Says: <claim>
- State: wrong — <what the bot misread>
- Fix: none.
- Dismiss: `/aino <one or two sentences naming the code that disproves the claim>`
- Status: proposed

### F3 — <one-line title>

- From: <account> (human) · comment id `<hash>`
- Sites: `path/to/svc.go:12`
- Says: <question>
- State: question
- Fix: none — asks for information.
- Reply: <the answer>
- Status: proposed

| ------- | ------------- | ------ | --------------------------------------------------- |

## Verification plan

- <the repo commands that must pass before the amend>
```

## Rules for the report

- One finding per rule or per point, not one per line. The site list carries the count. Two
  reviewers raising the same point is one finding credited to both.
- Say who wrote each finding and whether they block. The owner reads the report to decide what to
  spend the session on, and a blocking `-1` outranks six nits.
- Quote the claim in your own words, in one sentence, from the **last** message in the thread. Do
  not paste the whole comment.
- Every human finding carries a `Reply:` line, including the stale ones and the ones needing no
  edit. A thread with no reply is a thread the reviewer will raise again.
- A finding with no fix still appears, with the reason. That is half the value of the audit.
- Never write `Status: done` before Phase 6 runs, or `posted` / `dismissed` before Phase 8 runs.
- Every `/aino` draft carries its evidence in the draft text. A draft without evidence is not ready
  to post.
